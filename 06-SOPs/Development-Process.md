# Desenvolvimento

Requisitos e aceitação precedem implementação. Cada incremento tem responsável, ficheiros delimitados e critérios de revisão. Registar decisões que alteram arquitetura, âmbito ou operação.

Usar Git quando houver repositório configurado; não fazer push sem destino confirmado. Este projeto ainda não foi inicializado como repositório nesta entrega. Criar commits pequenos e manter segredos fora do controlo de versões.

Executar testes proporcionais ao comportamento alterado e registar resultado, versão e ambiente. Preparar staging e rollback antes de produção. O trabalho de QA segue [[Quality-Assurance]]; publicação segue [[Release-Process]].
